# Feature: Unit Test Implementation Continuation (07-03-27)

## Overview
This document outlines the continuous effort to achieve over 70% unit test coverage for the `warada_v2` project. This builds on the previous milestone (feature-unit-test-060226) which hit >50% coverage.

## Current State Analysis
Based on the JaCoCo test report generated on 2026-03-07, the overall instruction coverage is at **46.13%**. (The previous 50% must have fluctuated due to new code or partial test inclusion). 

The following packages/classes have been identified with poor coverage (<70%):
- **Models/DTOs**: `CrawlNettruyenSSEComic`, `ExtractedImage`, `ExtractedChapters$ChapterItem`, `ApiResponse` (0%).
- **Converters**: `CrawlStatusConverter`, `ImageTypeConverter` (0%).
- **Repositories**: `ImageRepositoryImpl`, `ComicRepositoryImpl`, `ChapterRepositoryImpl`, `TagRepositoryImpl` (0%).
- **Services**: `ImageServiceImpl` (0%), `NettruyenExtractorImpl` (~26%), `CrawlServiceImpl` (~58%).
- **Exceptions/Mappers**: `GlobalExceptionMapper`, `ConflictExceptionMapper` (0%).
- **Schedulers/Utils**: `FileTempClearer` (0%), `commons/Utils` (0%).

## Design & Strategy to Hit >70%

### Phase 1: Models & Converters (Low Effort, High Reward)
Many models and enums contain auto-generated bytecode or simple logic (Getters, Setters, Constructors, `equals`, `hashCode`).
1. Instantiate these objects.
2. Call all getters/setters.
3. Assert fields match.
4. Test Converter `convertToDatabaseColumn` and `convertToEntityAttribute` methods.

### Phase 2: Exceptions and Mappers
Testing exception classes and `ExceptionMapper` classes by manually triggering the mapper methods and verifying the `.toResponse()` or `.build()` structures. 

### Phase 3: Repositories
Since they are `PanacheRepositoryBase` implementations, we can write simple unit tests using Hibernate Reactive/Panache mocking features `PanacheMock`, or via standard `@QuarkusTest` if embedded DB is viable, allowing us to cover simple methods like `findById`, `persist`, etc. We will predominantly use mock-based tests or verify straightforward queries.

### Phase 4: Services and Schedulers
- `ImageServiceImpl`: Needs tests for fetching/saving images. Mock the `MinioClient` and Repositories.
- `FileTempClearer`: Mock the scheduler invocation and file deletion methods.
- `Utils`: Unit test the static utility methods directly.
- `NettruyenExtractorImpl` and `CrawlServiceImpl`: Expand existing test suites to cover edge cases and error handling branches.

## Monitoring & Execution
1. Implement the tests incrementally per phase.
2. Run `./gradlew clean test jacocoTestReport`.
3. Check the HTML/XML Jacoco reports to verify coverage climbs past the 70% threshold.
